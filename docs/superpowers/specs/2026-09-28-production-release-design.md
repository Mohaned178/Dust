# Dust — v1.0.0 Production Release Design

Status: approved in brainstorming session, 2026-09-28
Platform: Windows only (unchanged)
Stack: Electron + Node.js + React + TypeScript + Tailwind + Vite + electron-builder

## 1. Goal

Turn the merged MVP plus the uncommitted Startup Manager and Deep Uninstall work into a
shippable v1.0.0: a reproducible unsigned Windows installer published through GitHub
Releases, built by CI, on a linted and hardened codebase.

Success means:

1. `npm run dist -w app` produces `app/release/Dust-Setup-1.0.0.exe` from a clean checkout.
2. The packaged app launches, loads its renderer under a strict CSP, and the Dashboard,
   Startup Manager, and Deep Uninstall surfaces all open and function.
3. CI runs typecheck, lint, tests, and a production build on every push/PR to `master`.
4. A `v*` tag builds the installer and creates a draft GitHub Release with checksums.
5. Repo has LICENSE, CHANGELOG, version 1.0.0, Deep Uninstall docs, and a documented
   release process.

## 2. Decisions from brainstorming

| # | Decision |
|---|----------|
| 1 | **Unsigned.** No code-signing certificate yet. The release pipeline ships unsigned; electron-builder signing config is documented as a stub for later. |
| 2 | **Manual downloads.** No auto-update in v1.0.0. Installer attached to a GitHub Release. |
| 3 | **Include everything.** Startup Manager and Deep Uninstall ship in v1.0.0; the uncommitted working tree is reviewed, committed, and merged to `master`. |
| 4 | **MIT license.** LICENSE file plus `license` fields in all three package.json files. |
| 5 | **Generated placeholder icon.** Pine Teal mark generated by a committed script (no image tooling dependency); swappable later. |
| 6 | **electron-builder** for packaging (mature NSIS support, no native deps). |
| 7 | **ESLint 9 flat config + Prettier** for lint/format (Biome noted as the lighter alternative; rejected for ecosystem convention). |
| 8 | **GitHub Actions on windows-latest** for CI and releases; Node 22. |
| 9 | **Draft releases.** The release workflow creates a draft GitHub Release; a human reviews and publishes. |
| 10 | **Nothing pushes without the user.** Local commits per task are in scope; `git push`, tag creation, and publishing releases require explicit user action. |

## 3. Phase 1 — Review and land the branch work

The working tree on `feat/startup-manager` holds ~35 modified and ~30 untracked files
covering Startup Manager, System Info follow-ups, and Deep Uninstall. Deep Uninstall is
security-sensitive (registry reads/writes, file moves, process termination, elevation), so
landing includes a focused review before commit:

- **Protected paths.** Uninstall plan/execute must reuse the cleaner's protected-path guard;
  volume roots, `C:\Windows`, Program Files, ProgramData, and profile roots can never be
  deleted or moved.
- **IPC validation.** Every new renderer-reachable input (uninstall request, journal ids,
  registry ids, startup toggle ids) is validated in the host before use; forged ids are
  refused, matching the startup-toggle precedent.
- **Command execution.** Any spawned process (uninstaller invocation, PowerShell) uses
  fixed argument arrays, never shell interpolation of user-controlled strings.
- **Recovery/undo.** Backups and the journal are written before destructive steps; failures
  roll back or leave a restorable state; no path deletes without a prior backup.
- **Elevation handoff.** The pending-uninstall handoff file is validated on launch, is
  single-use, and cannot be replayed to act on a stale job.

Findings are fixed in place. Then the working tree is committed in logical feature commits
and `feat/startup-manager` is merged to `master` (fast-forward when possible, otherwise a
merge commit; no push).

## 4. Phase 2 — Repo hygiene

- `LICENSE` — MIT, `Copyright (c) 2026 Mohaned178`.
- `app/package.json` version `0.1.0` → `1.0.0` (the version electron-builder reads).
  Root and core stay private at `0.1.0`; their `license` fields become `MIT`.
- `CHANGELOG.md` — Keep a Changelog format, one 1.0.0 entry summarizing shipped features
  and the known unsigned/SmartScreen caveat.
- `.gitignore` — verify `app/release/` and `app/resources/*.ico` handling: `release/`
  is already ignored; generated icons are committed.

## 5. Phase 3 — Lint and format

- Root devDependencies: `eslint`, `@eslint/js`, `typescript-eslint`,
  `eslint-plugin-react-hooks`, `prettier`, `eslint-config-prettier`, `globals`.
- `eslint.config.mjs` at the root: `js.configs.recommended` + `tseslint.configs.recommended`
  (non-type-checked to start), `react-hooks` rules scoped to `app/renderer/**`, ignores for
  `dist/`, `release/`, `node_modules/`. `@typescript-eslint/no-explicit-any` downgraded to
  `warn` only if genuine occurrences require it.
- `.prettierrc.json`: `singleQuote: true`, `printWidth: 120`, `semi: true`, `trailingComma: "all"`.
- `.prettierignore`: `dist/`, `release/`, `node_modules/`, `package-lock.json`,
  `docs/superpowers/**` (historical docs stay as written), generated icons.
- Root scripts: `lint` (`eslint .`), `format` (`prettier --write .`),
  `format:check` (`prettier --check .`).
- One `chore: apply prettier formatting` commit if the sweep touches files; all ESLint
  findings fixed (not suppressed) unless a rule is demonstrably wrong for the codebase.

## 6. Phase 4 — Electron hardening

New `app/src/main/security.ts`:

- **CSP** injected via `session.defaultSession.webRequest.onHeadersReceived`, production only
  (dev server traffic is exempt so HMR keeps working):
  `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`.
  `style-src 'unsafe-inline'` is required by React inline style attributes. If `'self'`
  proves insufficient for `file://` loads during the smoke run, the smallest scheme-scoped
  allowance (`file:`) is added with a comment explaining why.
- **Window-open handler** on the main window's `webContents`: deny all (the renderer has no
  external links). If a link is added later it must go through `shell.openExternal` with an
  `https:` URL check.
- **Navigation guard**: `will-navigate` prevents anything other than the initially loaded
  app URL (prod) or the dev-server origin (dev).
- **Permissions**: `setPermissionRequestHandler` and `setPermissionCheckHandler` deny all;
  Dust needs no camera, microphone, geolocation, or notifications.
- **`app.setAppUserModelId('com.mohaned178.dust')`** for correct taskbar grouping and
  installer identity.
- **Dev-only flags**: `DUST_BENCH_ROOT` and `DUST_AUTO` are ignored when `app.isPackaged`.
- **Crash logging**: `process.on('uncaughtException')` / `('unhandledRejection')` append to
  `%APPDATA%\Dust\error.log`; `app.on('render-process-gone')` logs the reason. Existing
  startup-error logging is folded into one helper.
- **Renderer error boundary**: a top-level boundary in `app/renderer/src` showing a
  recovery screen (message + Reload button) instead of a blank window on a render error.

## 7. Phase 5 — Packaging

- Add `electron-builder` to `app` devDependencies; scripts: `dist`
  (`npm run build && electron-builder --win`), and root `dist:app`.
- `app/electron-builder.yml`:
  - `appId: com.mohaned178.dust`, `productName: Dust`,
    `copyright: Copyright © 2026 Mohaned178`
  - `directories: { output: release, buildResources: resources }`
  - `files: ["dist/**"]`, `asar: true`, `npmRebuild: false` (no native deps)
  - `win.target: nsis`, `win.icon: resources/icon.ico`, `win.arch: [x64]`
  - NSIS: assisted installer (`oneClick: false`), per-user (`perMachine: false`),
    choose-install-dir and desktop-shortcut options, `artifactName:
    ${productName}-Setup-${version}.${ext}`
  - Commented signing stub: `# win.certificateFile` / `# win.certificatePassword`
    (or Azure Trusted Signing) for when a certificate exists.
- **Icon generator** `app/scripts/make-icon.mjs` (pure Node, no dependencies): draws a
  rounded Pine Teal (#0f6e6e) square with three shrinking white bars (the "space going
  down" mark) with 4× supersampled anti-aliasing, encodes 16/24/32/48/64/128/256 px
  entries as BMP/DIB inside `resources/icon.ico` and a 512 px PNG at
  `resources/icon.png`. Generated files are committed; the script is re-runnable.
- `app/resources/` becomes `directories.buildResources`, avoiding the `build/` gitignore
  entry and electron-builder's default output collision with `app/dist/`.

## 8. Phase 6 — CI/CD

`.github/workflows/ci.yml` — on push/PR to `master`, `windows-latest`, Node 22 with npm
cache: `npm ci` → `npm run typecheck` → `npm run lint` → `npm test` → `npm run build:app`.

`.github/workflows/release.yml` — on `v*` tags, `windows-latest`, `permissions:
contents: write`: `npm ci` → typecheck → test → `npm run dist -w app` → write
`sha256sums.txt` via `Get-FileHash` → `gh release create "$env:GITHUB_REF_NAME" --draft
--generate-notes` with the installer and checksums attached. The draft is reviewed and
published manually.

Neither workflow pushes to the repo; releases are tag-driven and tags are created by the
user (or by the user running `git push origin v1.0.0` after the merge).

## 9. Phase 7 — Documentation

- `README.md`: new **Install** section near the top (Releases download, SmartScreen "More
  info → Run anyway" note for the unsigned build, build-from-source kept); new **Deep
  Uninstall** feature section; scripts table gains `lint`, `format`, `dist:app`; Roadmap
  drops installed-apps manager and gains release-pipeline follow-ups (signing, auto-update).
- `PROJECT_BRIEF.md`: "Current state" and MVP feature list reflect Startup Manager, Deep
  Uninstall, System Info, v1.0.0 packaging, and CI.
- `CHANGELOG.md` is the single source for release notes and needs no further edits unless
  review changes the shipped feature list.

## 10. Verification

- `npm run typecheck`, `npm test`, `npm run lint` green at the root.
- `npm run dist -w app` on a clean build produces `app/release/Dust-Setup-1.0.0.exe` and
  `app/release/win-unpacked/Dust.exe`.
- Smoke run of `win-unpacked/Dust.exe` (or `npm start -w app` against the production build):
  window loads with CSP active and no CSP violations in the console, Dashboard renders,
  Startup Manager and Deep Uninstall open, System Info renders.
- `npm run build:app` remains the fast production build; CI config mirrors the local
  commands exactly.
- The release workflow is only exercised on a real tag push, which the user controls.

## 11. Non-goals

- Code signing, auto-update, crash-reporting SaaS, telemetry.
- Cross-platform builds, Windows ARM64, portable/zip targets.
- Installer branding beyond electron-builder defaults plus the generated icon.
- Performance work, feature work, or refactors unrelated to the phases above.
